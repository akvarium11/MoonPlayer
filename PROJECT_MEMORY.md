## 📌 1. Обзор проекта (Overview)

**MoonPlayer** — это гибридный настольный аудио-плеер для локальной медиатеки с акцентом на современный UI/UX, высокую производительность и глубокую интеграцию с ОС и Discord.

- **Тип приложения**: Гибридное десктопное приложение (Native Shell + Node.js Backend Daemon + Web Client UI).
- **Платформы**: Windows 10/11 (MinGW / Edge WebView2) и Linux (GTK-3 / WebKit2GTK).
- **Лицензия**: GPL-3.0.
- **Порт по умолчанию**: `7644`.

## 🔑 4. Ключевые компоненты и функционал

### 4.1. Поддержка аудиоформатов и FLAC-бейдж (`[F]`)
- **Поддерживаемые форматы**: `.mp3`, `.flac`, `.ogg`, `.wav`, `.m4a`, `.aac`, `.webm`, `.opus`.
- **FLAC-бейдж (`.flac-badge`)**:
  - Минималистичная векторная иконка в стиле Explicit (`E`), но с буквой **`F`**.
  - **Без фона** (`background: transparent;`): аккуратный прозрачный контур без закрашивания.
  - **Идеальное центрирование буквы "F"**: векторный контур SVG с математическим центрированием по осям X и Y ($7.0, 7.0$), не зависящий от шрифтов ОС, масштабирования или наведения курсора.
  - **Защита от наплыва на длинных треках**: строгие ограничения ширины (`flex: 0 1 auto`, `min-width: 0`, `max-width: 100%`, `overflow: hidden`, `padding-right` на панели острова 112px с запасом под кнопки Lock/Lyrics/Queue). Текст обрезается многоточием (`text-overflow: ellipsis`), бейдж всегда остается в границах блока и не налезает на смежные элементы интерфейса.
  - Размеры: базовый $14\times14$ px, `.flac-badge-mini` ($11\times11$ px для компактного острова) и `.flac-badge-queue` ($12\times12$ px для очереди).
  - Подсказка при наведении: `title="FLAC Lossless Audio"`.
  - Отображается:
    1. В строках треков альбомов, плейлистов и библиотеки (`appendMoreSongs`).
    2. В результатах поиска треков (`searchType === 'song'`).
    3. В очереди Dynamic Island (`updateIslandQueue`).
    4. В раскрытом плеере Dynamic Island (`#track-title`).
    5. В компактном плеере Dynamic Island (`#mini-track-title`).

### 4.2. Dynamic Island
- **Компактный режим**: Название трека, статусная анимация аудиоволн (mini-waveform), мини-обложка трека.
- **Раскрытый режим**:
  - Полноразмерная вращающаяся обложка винила с анимацией смены трека.
  - Управление воспроизведением (Shuffle, Prev, Play/Pause, Next, Loop One/All/Off).
  - Слайдер таймлайна с точной перемоткой и громкость с Mute.
  - Кнопки переключения секций: Lyrics (текст песни), Queue (очередь треков), Lock (закрепление открытого состояния).
  - Аудио-визуализатор на Canvas.

### 4.3. 10-полосный ISO-эквалайзер
- Частоты: `32Hz`, `64Hz`, `125Hz`, `250Hz`, `500Hz`, `1kHz`, `2kHz`, `4kHz`, `8kHz`, `16kHz`.
- Регулятор Preamp (Gain от -12dB до +12dB).
- Интерактивный холст графика АЧХ (интерполяция кривой сплайном в реальном времени).
- Встроенные пресеты (Rock, Pop, Bass Boost, Vocal, Jazz, EDM, Hip-Hop, Classical, Acoustic, Deep).
- Сохранение и удаление пользовательских пресетов в `localStorage`.

### 4.4. Discord Rich Presence
- Фоновый клиент RPC (`discord-rpc`).
- Default Client ID зафиксирован: `1543154845958275114` (опция ручного ввода Application ID скрыта/удалена из UI настроек).
- Передает в профиль: название трека, артиста, альбом, таймлайны воспроизведения (elapsed/remaining), статус паузы.
- Интеллектуальный поиск обложек через Deezer, iTunes Search API и Last.fm с локальным кэшированием в `cover_cache.json`.

### 4.5. Кэширование метаданных
- Быстрое сканирование больших библиотек благодаря IndexedDB (`moonplayer_metadata_db`).
- Парсинг тегов через `jsmediatags` пачками с ограничением конкурентности.
- Фоллбэк-парсинг из файловой структуры (`Artist - Title.ext` или `.../Artist/Album/Track.ext`).

### 4.6. Интеграция с SoundCloud (Streaming, Search & Unified Browsing)
- **Единая вкладка SoundCloud (Unified Multi-Entity Browsing)**:
  - Все сущности SoundCloud — **треки, альбомы, плейлисты и артисты** — объединены в одной вкладке поиска в левой панели (`searchType === 'soundcloud'`).
  - Липкая панель подвкладок/фильтров под поисковой строкой: `All` | `Tracks` | `Albums` | `Playlists` | `Artists`.
  - **Режим `All`**:
    - При пустом поиске: баннер профиля пользователя с аватаром и статистикой, горизонтальная полка созданных плейлистов пользователя (`Your Playlists`), список лайков (`SoundCloud Likes`) с кнопкой мгновенного воспроизведения `Play All`.
    - При поисковом запросе: параллельный поиск через `/api-v2/search`, отображение горизонтальных карточек для найденных **Артистов**, **Альбомов**, **Плейлистов** (с кнопками "See all" для быстрого перехода в соответствующую подвкладку) и вертикальный список найденных **Треков**.
  - **Интерактивные профили артистов (`openSoundCloudArtist`)**:
    - При клике на артиста в правой части открывается детальный профиль: круглый аватар $50\%$, имя, счетчик подписчиков, биография из SoundCloud.
    - Горизонтальная полка дискографии артиста (альбомы и плейлисты) и список лучших треков с кнопкой воспроизведения всех треков (`Play All`), бейджами и скачиванием.
  - **Интерактивные альбомы и плейлисты (`openSoundCloudAlbum` / `openSoundCloudPlaylist`)**:
    - При клике на альбом или плейлист автоматически загружаются и резолвятся треки (включая пакетный резолвинг заглушек через `/tracks?ids=...`).
    - Отображается полноразмерная обложка $500\times500$, автор, год, число треков и полный список с бейджами, воспроизведением и кнопками добавления.
- **Архитектура сервиса (`soundcloud_service.js`)**:
  - Авторизация через `Authorization: OAuth <token>` (SoundCloud API v2).
  - Поиск треков, альбомов, плейлистов и артистов (`searchTracks`, `searchAlbums`, `searchPlaylists`, `searchArtists`, `searchAll`).
  - Загрузка плейлистов/альбомов (`getPlaylist`) и профилей артистов (`getArtist`).
  - Потоковый HTTP-прокси (`/api/soundcloud/stream/:id`) с полной поддержкой Range-запросов (HTTP 206 Partial Content), `Accept-Ranges: bytes` и заголовков CORS `Access-Control-Allow-Origin: *` для корректной интеграции с HTML5 Audio, Web Audio API, спектроанализатором (визуализатором) и эквалайзером.
  - Скачивание треков в библиотеку (`/api/soundcloud/download-to-library`) с автоматической генерацией ID3v2 тегов (название, артист, альбом, год, обложка в высоком разрешении $500\times500$) и сохранением в подпапку `SoundCloud/`.
- **Минималистичный SoundCloud-бейдж (`.sc-badge`)**:
  - Полностью повторяет геометрию и стиль `.flac-badge`: тонкая рамка $14\times14$ px со скругленными углами ($rx=2.5$), без фона (`background: transparent`).
  - Вместо буквы "F" внутри идеально отцентрирован минималистичный векторный логотип облака SoundCloud белого цвета (центр $7.0, 7.0$).
  - Применяется как к потоковым трекам SoundCloud, так и к трекам, скачанным из SoundCloud в локальную библиотеку.
  - Отображается в строках треков, результатах поиска, очереди, а также в компактном (`flac-badge-mini`) и раскрытом Dynamic Island.
- **Безопасность токенов (Security)**:
  - Строгая изоляция учетных данных: `oauth_token` хранится исключительно в локальном серверном файле `soundcloud_config.json`, внесенном в `.gitignore`.
  - Эндпоинт `/api/soundcloud/config` никогда не отдает сам токен наружу (`{ enabled: true, hasToken: true, user: {...} }`).
- **Интеграция с плейлистами и очередью**:
  - Треки идентифицируются по URI-схеме `soundcloud:<id>`.
  - Клиентский кэш `moonplayer_sc_cache` в `localStorage` гарантирует мгновенное восстановление треков в пользовательских плейлистах и очереди воспроизведения даже после перезапуска приложения.
  - **Воспроизведение прямо из поиска**: мгновенный запуск и переключение паузы по клику на трек в результатах поиска с динамическим оверлеем play/pause и корректной регистрацией в глобальном реестре треков.
  - **Динамический акцентный цвет**: полное соответствие выбранному пользователем акцентному цвету `var(--accent)` (через `color-mix`), без жестко зашитого оранжевого цвета.
  - **Адаптивность и скроллбары**: горизонтальные полки и подвкладки оснащены плавным скроллингом колесом мыши и drag-to-scroll (`enableHorizontalScroll`), скрыты системные скроллбары Chromium/Windows, блоки не сминаются при изменении размера окна (`flex-shrink: 0; min-height: 155px;`).
  - **Отображение обложки в Discord RPC**: при воспроизведении треков из SoundCloud прямая ссылка на обложку передается в RPC и автоматически преобразуется в максимальное разрешение $500\times500$ (`t500x500`), с кнопкой перехода на трек в SoundCloud.
  - **Фикс выпадающего списка**: иконка SoundCloud (и остальных типов) жестко зафиксирована слева от текста в одну строку без вертикального переноса.

## 🛠️ 5. Сборка и распространение

### 5.1. Автономный переносимый бинарник (Один `.exe` файл без зависимостей)
Для конечных пользователей собран полностью автономный исполняемый файл **`dist/MoonPlayer.exe`** (~96 MB):
- **Не требует установки Node.js, npm, Python или библиотек на компьютере пользователя**.
- Включает в себя всё: рантайм, Chromium окно, Express бэкенд, Discord RPC, шрифты и ассеты.
- Запускается в один клик на любой Windows 10/11:
```bash
npm run build        # Собирает автономный dist/MoonPlayer.exe (portable)
npm run build:installer # Собирает полноценный Windows инсталлятор (NSIS setup)
```

### 5.2. Запуск в режиме разработки:
```bash
npm start            # Запуск десктопного приложения в режиме разработки (Electron)
npm run server       # Запуск только фонового сервера Node.js (http://localhost:7644)
```

### 5.3. Классический C++ лаунчер (WebView2):
- **Windows (MinGW/GCC)**:
  ```cmd
  windres resources.rc -o resources.o
  g++ -std=c++17 launcher.cpp resources.o -o MoonPlayer.exe -Iwebview2_sdk/build/native/include -lws2_32 -lole32 -lversion -lshlwapi -luuid -luser32 -lgdi32 -ldwmapi -mwindows -municode
  del resources.o
  ```
- **Linux (GCC / GTK3)**:
  ```bash
  chmod +x build_linux.sh && ./build_linux.sh
  ```

5. **SoundCloud Integration & UI Fixes (2026-09)**:
   - **Stub Resolution**: В `soundcloud_service.js` реализован метод `resolvePlaylistStubs` с параллельным chunked-фетчингом батчами по 50 треков (`Promise.all`), решая проблему появления «Untitled» и заглушек в больших плейлистах/альбомах.
   - **Полноэкранный режим в вертикальной ориентации**: В CSS устранён фантомный блок `min-height: 380px` на `.panel-left` при `.maximized-view`, добавлены `display: none !important; min-height: 0px !important;`, а также классы `.has-maximized` на `.main-container` и `.bio-card` (`overflow: hidden; height: 100% !important;`), благодаря чему правая панель и список треков гарантированно разворачиваются на 100% высоты экрана как при узком окне (`<= 900px`), так и в портретной ориентации.
   - **Гарантированный запуск трека с первого клика**: В `appendMoreSongs` и `playTrack` устранена ошибка, из-за которой новые или подгруженные треки без предрегистрации имели `globalIndex === undefined`, приводя к игнорированию первого клика до клика по другому элементу. Теперь каждый трек валидируется, гарантированно регистрируется в `allSongs` с присвоением `globalIndex` и `src`, а `playTrack` принимает как индекс, так и сам объект трека.
   - **Клик по треку и строке**: Удален захват клика по названию трека (`.song-title`) и названию альбома (`.song-album`), ранее вызывавший открытие фейковых альбомов. Теперь клик по всей строке (название, альбом, фон, длительность) мгновенно запускает воспроизведение (или ставит на паузу).
   - **Переход к профилю артиста**: Добавлен обработчик клика в левой панели для `searchType === 'artist'`, а `selectArtistByName` получил 3-уровневый fallback (локальный индекс -> поиск в треках -> автопоиск и открытие страницы исполнителя в SoundCloud с дискографией).
   - **Лимит имён исполнителей альбомов**: В `buildLibraries()` предотвращена склейка сотен артистов в одну строку (при >3 артистах выводится `Various Artists`).

7. **SoundCloud Streaming & Full Playlist Resolution Fixes (2026-09)**:
   - **Устранение фриза загрузки аудио (Connection Pool Saturation)**: В `fetchAudioDuration` (`script.js`) устранена критическая утечка соединений, при которой для каждого трека в отображаемом списке создавался `new Audio()`, приводивший к открытию до 50 одновременных соединений для загрузки MP3 и исчерпанию пула HTTP-сокетов Chromium (лимит 6 сокетов на origin). Теперь треки используют уже известную длительность из метаданных SoundCloud без фонового скачивания потоков, для SoundCloud треков полностью исключено создание сетевых `new Audio()`, а длительность отображается мгновенно.
   - **Индикация загрузки и устранение блокировки повторного клика**: Добавлен флаг состояния `isTrackLoading`. При клике на трек немедленно активируется подсветка и спиннер загрузки (`fa-spinner fa-spin`), а клики по загружающемуся треку больше не вызывают вызов `togglePlayPause()`, который раньше прерывал воспроизведение ошибкой `AbortError` и блокировал плеер до переключения на другую песню. Добавлены обработчики событий `playing`, `pause`, `waiting`, `error` на `bgAudio`.
   - **Кэширование транскодирований и дедупликация потоков**: В `soundcloud_service.js` реализован кэш `transcodingsCache`, сохраняющий медиа-транскодирования треков сразу при их получении из плейлистов/поиска. Это исключило лишний round-trip запрос к `/tracks/:id` при старте стриминга (ускорение старта трека с ~1000мс до ~250мс). Добавлен `inFlightStreamUrls` для предотвращения дублирующих запросов при Range-пробах браузера, и `AbortController` в `pipeStream` для немедленной остановки апстрим-загрузок с CDN при переключении треков.
   - **Загрузка плейлистов и альбомов без ограничения в 5 треков**: В `openSoundCloudPlaylist` и `openSoundCloudAlbum` устранена ошибка в проверке `needsFetch`, из-за которой наличие 5 треков по умолчанию в результатах поиска SoundCloud ошибочно воспринималось как полная загрузка плейлиста. Теперь флаг `isFullyLoaded` и сверка с `trackCount` гарантируют полный запрос к `/api/soundcloud/playlist/:id` и отображение всех треков плейлиста (включая 100+ и 200+ треков).

14. **Preloader 0% Freeze / Temporal Dead Zone Fix (2026-09)**:
    - **Причина зависания на 0%**: При запуске приложения на этапе `DOMContentLoaded` вызывалась функция `updateAccentColor(accentColor)` на строке 86. Внутри этой функции производилось присваивание `cachedAccentColor = color;`. Однако переменная `let cachedAccentColor = '#ffffff';` была объявлена ниже (на строке 88). Согласно спецификации ECMAScript, переменные `let` до момента их лексической декларации находятся в Temporal Dead Zone (TDZ). Из-за этого обращение выбрасывало необработанное исключение `ReferenceError: Cannot access 'cachedAccentColor' before initialization`.
    - **Последствия ошибки**: Исключение прерывало выполнение всего блока `DOMContentLoaded`, в результате чего интервал прелоадера (`setInterval(..., 100)`) так и не запускался, а интерфейс плеера оставался заблокирован на 0% как на ПК, так и на Android.
    - **Исправление**: Декларация `let cachedAccentColor = accentColor;` перенесена вверх к чтению акцентного цвета из `localStorage` (до первого вызова `updateAccentColor`). Синтаксис и запуск проверены через Node.js с эмуляцией DOM.
    - **Синхронизация и билд**: Изменения синхронизированы в `public/script.js` и `android/app/src/main/assets/script.js`. APK пересобран и сохранен в `dist/MoonPlayer.apk`.

        - В [public/riff-ui.js](file:///G:/Repository/MoonPlayerApp/public/riff-ui.js) при клике на строку трека мгновенно выставляются классы `.playing` и `.loading`, обновляются метаданные в плейбаре и включается круговой спиннер `#playbar-spinner`.

    - **3. Ложное определение воспроизведения в SoundCloud-поиске и дедупликация треков между альбомами**:
      - **Причина**:
        - В `registerSoundCloudTrack()` ([public/script.js](file:///G:/Repository/MoonPlayerApp/public/script.js)) выполнялся поиск `allSongs.find(s => ... || isSameTrack(s, track))`. Функция `isSameTrack` сравнивала название и автора без проверки платформы. В результате локальный трек с похожим названием ошибочно считался SoundCloud-треком: ему перезаписывался `id` на ID из SoundCloud, а объекту из SoundCloud присваивался `globalIndex` локального трека. При открытии поиска SoundCloud трек ошибочно определялся как уже играющий.
        - В `deduplicateSongs()` ([public/script.js](file:///G:/Repository/MoonPlayerApp/public/script.js)) и `deduplicateTrackList()` ([public/riff-ui.js](file:///G:/Repository/MoonPlayerApp/public/riff-ui.js)) ключ дедупликации состоял только из `${normTitle}:::${normArtist}` без учета альбома и пути к файлу. Если у исполнителя была одна и та же песня в разных альбомах (альбом, сингл, переиздание), дедупликатор выбрасывал вторую песню, лишая второй альбом трека.
      - **Решение**:
        - В `isSameTrack()` добавлена строгая проверка платформ: если один трек локальный, а второй — из SoundCloud (`isSoundCloud(t1) !== isSoundCloud(t2)`), возвращается `false`. Локальные и SoundCloud-треки изолированы.
        - В `registerSoundCloudTrack()` сопоставление ведется исключительно среди существующих онлайн-треков SoundCloud, локальные файлы библиотеки не затрагиваются.
        - В `deduplicateSongs()` и `deduplicateTrackList()` в ключ дедупликации добавлен альбом (`title:::artist:::album`), а также гарантированно сохраняются все треки с разными путями к файлам (`path`). Одноименные треки из разных альбомов больше не удаляются.


37. **Исправление сбоя паузы по пробелу в Riff UI и приоритизация треков в поиске SoundCloud (2026-11)**:
    - **1. Остановка трека лишь на миллисекунду при нажатии пробела в Riff UI**:
      - **Причина**: В [public/riff-ui.js](file:///G:/Repository/MoonPlayerApp/public/riff-ui.js) был зарегистрирован отдельный глобальный слушатель клавиатуры `window.addEventListener('keydown')`, перехватывавший `e.code === 'Space'` и вызывавший `window.MoonPlayer.togglePlayPause()`. При этом в [public/script.js](file:///G:/Repository/MoonPlayerApp/public/script.js) уже существовал глобальный слушатель `document.addEventListener('keydown')`, также вызывавший `playBtn.click()` при нажатии `Space`. При нажатии пробела в интерфейсе Riff срабатывали оба обработчика подряд в рамках одного события: сначала `script.js` ставил воспроизведение на паузу, а затем через долю миллисекунды `riff-ui.js` снова возобновлял воспроизведение (или наоборот). Аналогично клавиша `KeyM` дважды инвертировала mute, а клавиша `KeyL` одновременно ставила лайк и переключала панель текста песни.
      - **Решение**: Из [public/riff-ui.js](file:///G:/Repository/MoonPlayerApp/public/riff-ui.js) удалены дублирующие обработчики `Space` и `KeyM`, общее управление воспроизведением делегировано базовому обработчику в [public/script.js](file:///G:/Repository/MoonPlayerApp/public/script.js). В [public/script.js](file:///G:/Repository/MoonPlayerApp/public/script.js) для `KeyL` добавлена проверка режима `mode-riff`, чтобы в интерфейсе Riff клавиша `L` переключала только панель текста песни.
    - **2. Приоритизация выдачи треков перед исполнителями и плейлистами в поиске SoundCloud**:
      - **Причина**: В разметке [public/index.html](file:///G:/Repository/MoonPlayerApp/public/index.html) и в функции `renderSearchResultsSections()` в [public/riff-ui.js](file:///G:/Repository/MoonPlayerApp/public/riff-ui.js) секции результатов поиска располагались в порядке: Artists (`#search-artist-card-container`), затем Albums/Playlists (`#search-albums-container`), и лишь в самом конце — Tracks (`#search-tracks-list`). Из-за этого пользователю в результатах SoundCloud приходилось пролистывать карточки артистов и альбомов до списка песен. В Moon UI ([public/script.js](file:///G:/Repository/MoonPlayerApp/public/script.js)) секция артистов шла после плейлистов и альбомов.
      - **Решение**: В [public/index.html](file:///G:/Repository/MoonPlayerApp/public/index.html) и [public/riff-ui.js](file:///G:/Repository/MoonPlayerApp/public/riff-ui.js) контейнер треков `#search-tracks-list` перенесен на первое место перед исполнителями и альбомами. В функции `renderSearchResultsSections()` треки выводятся первыми, затем исполнители, затем плейлисты и альбомы. В [public/script.js](file:///G:/Repository/MoonPlayerApp/public/script.js) порядок секций в `renderSoundCloudPanel()` унифицирован: 1. Tracks, 2. Artists, 3. Playlists, 4. Albums.
